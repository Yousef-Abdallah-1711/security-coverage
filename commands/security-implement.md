# /security-implement

Use the `security-coverage` skill and run only its **security-implement** stage. A plan is not approval. Before any change, present the exact phase, task IDs, file scope, commands and safety classes, side effects, rollback, and verification; ask for explicit approval for that scope. If approval is absent, stop without changes. Apply only the approved scope, record real results, and stop at the phase boundary or any blocker. `--dry-run` is prompt-level and must stop before mutation; `--phase-only` is prompt-level and never authorizes work. If the canonical skill or its references are unavailable, stop and report that prerequisite.
